# 야간 자율 작업 계획 · DoD 생성과 검수 판정 고도화

작성: 2026-08-22 · 브랜치 `feat/dod-verification-metrics`

이 문서는 야간 반복 작업의 기준점이다. 매 반복마다 「진행 로그」를 갱신하고,

## 1. 문제 진단 (2026-08-22 확인)

이틀간 프롬프트를 고쳐도 개선이 보이지 않았던 원인은 프롬프트가 아니라 **계측**이다.

| # | 문제 | 근거 |
|---|---|---|
| 1 | URL 명시율 정규식이 URL 아닌 것을 센다 | `benchmark_105_dataset.mjs:243`의 `/\/([a-zA-Z0-9_\-:]+)/`가 `CSV/Excel`, `ERP/CRM`, `A/B`에 매칭. 실행해 확인함 |
| 2 | 리포트의 달성 여부가 하드코딩된 `✅` | `benchmark_105_dataset.mjs:396` 문자열 리터럴. 89.9%가 "90% 이상" 목표에 ✅로, 11.74초가 "< 8초" 목표에 ✅로 찍힘 |
| 3 | 생성된 DoD 원문이 저장되지 않음 | `EXP_105_BENCHMARK_RESULTS.json`에 개수·비율만 있음. 재채점·프롬프트 간 diff 불가 |
| 4 | 정작 목표인 지표가 없음 | `automation_ready` 도달률, False FAIL, False PASS를 재는 코드가 없음. CLAUDE.md §13은 자동 판정 정확도 90%를 목표로 명시 |
| 5 | SOW 프롬프트가 5곳에 복붙 | `analyze.ts` + `test_live_run.mjs` + `test_model_v2.mjs` + `run_exp7_eval.mjs` + `benchmark_105_dataset.mjs`. 드리프트 확실 |

**결론**: 눈금이 고장난 저울 위에서 이틀을 보냈다. 계측기부터 고치고 그 위에서 개선한다.

---

## 2. 단계

- **A. 계측기 수리** — 정직한 DoD 지표 + 지표 자체의 단위 테스트 + 생성 결과 전문 보존 + 프롬프트 단일화
- **B. 검수 가능성 계측** — DoD → 계약 분석 → 질문 자동응답 → atom 조합 → 엄격 파서. `automation_ready` 도달률과 거부 사유 분포. 네트워크는 OpenAI만 필요
- **C. 판정 정확도 계측** — 픽스처 앱 정상판/고장판에 조합된 스펙을 실제 실행. False FAIL / False PASS 측정
- **D. 지표 기반 개선 반복** — A~C 지표를 보며 프롬프트·조합 규칙·atom 어휘를 고침

## 3. 성공 기준

baseline을 먼저 측정하고, 아래를 만족하면 정지한다.

| 지표 | 목표 | baseline | 현재 |
|---|---|---|---|
| 실제 URL 경로 명시율 | ≥ 90% | 미측정 | — |
| 역량 서술('~가능함') 비율 | ≤ 5% | 미측정 | — |
| 체언 종결 준수율 | ≥ 95% | 미측정 | — |
| 단일 검증 원자성 | ≥ 95% | 미측정 | — |
| `automation_ready` 도달률 | baseline +20%p | 미측정 | — |
| **False FAIL (정상 앱 오판)** | **0%** | 미측정 | — |
| False PASS (고장 앱 통과) | ≤ 10% | 미측정 | — |

**정지 조건**: 전 지표 달성 / 토큰 소진 / 3회 연속 지표 개선 없음 / OpenAI 사용액 $20 도달
