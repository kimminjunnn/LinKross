동네에서 세탁소를 운영하고 있는데, 픽업과 배송 주문을 전부 전화와 카카오톡으로 받다 보니 관리가 안 됩니다. 어떤 손님이 언제 세탁물을 맡겼는지, 지금 세탁 중인지 배송 중인지 헷갈리고, 배송 기사님이 여러 명이다 보니 누가 어떤 주문을 담당하는지도 수기로 적어야 합니다. 손님이 앱에서 직접 픽업을 요청하고, 세탁물이 지금 어느 단계에 있는지 확인할 수 있고, 저와 기사님들은 전체 주문을 한눈에 관리할 수 있는 웹 서비스를 만들고 싶습니다.

주요 사용자는 세탁물을 맡기는 일반 고객, 픽업·배송을 담당하는 배송 기사, 그리고 세탁소를 운영하는 관리자(저)입니다. 서비스는 반응형 웹으로 만들고, 특히 고객이 픽업을 요청하고 상태를 확인하는 화면과 기사가 담당 주문을 확인하는 화면은 모바일에서 편하게 써야 합니다.

필수 기능은 다음과 같습니다.

**1. 회원가입 및 로그인**
고객은 이메일과 비밀번호로 회원가입하고 로그인할 수 있어야 합니다. 로그인 상태는 새로고침 후에도 유지되어야 하고, 로그아웃하면 세션이 종료되어야 합니다. 존재하지 않는 계정이나 잘못된 비밀번호로 로그인 시도 시 이해할 수 있는 오류 메시지를 보여주세요. 기사와 관리자는 고객과 별도의 계정 유형으로 구분되어야 하며, 관리자가 기사 계정을 생성해서 발급하는 방식으로 해주세요(기사 자체 회원가입은 없음).

**2. 픽업 주소 등록**
고객은 픽업 받을 주소를 하나 이상 등록할 수 있어야 합니다. 주소에는 별칭(집/회사 등), 상세 주소, 픽업 시 요청사항(공동현관 비밀번호 등)을 포함할 수 있습니다. 등록한 주소 중 하나를 기본 주소로 지정할 수 있어야 합니다.

**3. 픽업 주문 요청**
고객은 등록된 주소 중 하나를 선택하고, 세탁물 종류(일반 세탁/드라이클리닝/이불류 등)와 예상 수량, 픽업 희망 날짜와 시간대(오전/오후/저녁 중 선택)를 입력해 픽업을 요청할 수 있어야 합니다. 요청이 등록되면 주문이 생성되고 상태는 "픽업 대기"로 시작해야 합니다. 특이 요청사항(급한 얼룩 제거 등)을 자유 텍스트로 남길 수 있으면 좋겠습니다.

**4. 주문 상태 파이프라인**
주문 상태는 최소한 다음과 같이 구분됩니다.
- 픽업 대기
- 픽업 완료
- 세탁 중
- 세탁 완료 (배송 대기)
- 배송 중
- 배송 완료
- 취소됨

각 상태는 담당자(기사 또는 관리자)가 변경하며, 상태가 바뀌면 고객 화면에 즉시 반영되어야 합니다. 상태는 정해진 순서대로만 진행되어야 하고, 예를 들어 "픽업 대기" 상태에서 바로 "배송 완료"로 건너뛸 수 없어야 합니다.

**5. 기사 배정**
관리자는 픽업 대기 중인 주문을 특정 기사에게 배정할 수 있어야 합니다. 기사는 로그인 후 자신에게 배정된 주문만 볼 수 있어야 하고, 다른 기사에게 배정된 주문은 볼 수 없어야 합니다. 기사는 배정된 주문의 상태를 "픽업 완료"로 변경할 수 있고, 이후 관리자가 "세탁 중"으로 변경하면 세탁이 끝난 뒤 다시 배송 기사에게 배정되어 "배송 중", "배송 완료"까지 처리됩니다. 배정 로직이 복잡하면 MVP에서는 픽업 담당과 배송 담당을 굳이 구분하지 않고 하나의 기사가 처음부터 끝까지 담당해도 됩니다.

**6. 고객 주문 목록 및 상세**
고객은 자신의 전체 주문을 목록으로 확인할 수 있어야 하고, 진행 중인 주문과 완료된 주문을 구분해서 볼 수 있어야 합니다. 주문 상세에서는 현재 상태, 픽업 주소, 세탁물 종류, 담당 기사(배정된 경우), 상태 변경 이력(언제 어떤 상태로 바뀌었는지)을 확인할 수 있어야 합니다.

**7. 주문 취소**
고객은 "픽업 대기" 상태인 주문에 한해 직접 취소할 수 있어야 합니다. 이미 "픽업 완료" 이후 단계로 넘어간 주문은 고객이 직접 취소할 수 없고, 관리자에게 문의하도록 안내해주세요. 취소된 주문은 상태가 "취소됨"으로 바뀌고 목록에서 계속 조회는 되어야 합니다(삭제되면 안 됨).

**8. 재주문**
고객은 과거 완료된 주문을 보고 "다시 주문하기" 버튼으로 동일한 주소와 세탁물 종류를 그대로 채운 새 픽업 요청 화면으로 이동할 수 있으면 좋겠습니다. 날짜와 시간대는 새로 선택해야 합니다.

**9. 중복 요청 방지**
고객이 같은 주소로 같은 날짜, 같은 시간대에 이미 픽업 대기 중인 주문이 있는 상태에서 또 요청을 시도하면, 중복 요청일 수 있다는 안내를 보여주고 그대로 진행할지 확인하게 해주세요. 저장 버튼을 실수로 여러 번 눌러도 동일 주문이 중복 생성되면 안 됩니다.

**10. 알림 및 처리 상태 표시**
주문 상태가 바뀔 때마다 고객이 화면에서 바로 확인할 수 있어야 합니다. 이메일, SMS, 푸시 알림은 이번 MVP 범위에 포함하지 않고, 서비스 내 화면 표시로 충분합니다.

**11. 관리자 대시보드**
관리자는 오늘 픽업 예정 건수, 오늘 배송 예정 건수, 현재 세탁 중인 건수, 기사별 담당 건수를 한 화면에서 확인할 수 있어야 합니다. 복잡한 매출 통계나 리포트는 이번 MVP에서 제외합니다.

**12. 관리자 주문 관리**
관리자는 전체 주문을 상태별로 필터링해서 볼 수 있어야 하고, 고객명이나 주소로 검색할 수 있어야 합니다. 특정 주문을 선택해 상태를 직접 변경하거나 기사를 재배정할 수 있어야 합니다.

**13. 관리자 고객 관리**
관리자는 전체 고객 목록을 조회할 수 있어야 하고, 특정 고객을 선택하면 그 고객의 전체 주문 이력을 확인할 수 있어야 합니다.

**14. 권한과 보안**
고객은 자신의 주문과 주소만 조회하거나 수정할 수 있어야 하고, 다른 고객의 주문에는 URL을 직접 입력해도 접근할 수 없어야 합니다. 기사는 자신에게 배정된 주문 외에는 조회할 수 없어야 합니다. 관리자 전용 화면과 기능은 관리자 계정만 접근할 수 있어야 하며, 권한 검사는 화면뿐 아니라 서버에서도 이루어져야 합니다.

**15. 오류 및 상태 처리**
네트워크 오류나 서버 오류가 발생해도 서비스 전체가 먹통이 되면 안 되고, 사용자가 다시 시도할 수 있어야 합니다. 로딩 중, 데이터 없음, 요청 실패 상태를 화면에서 구분해서 보여주세요.

**16. 데이터 구조**
User(역할: 고객/기사/관리자), Address, Order, OrderStatusHistory, Driver 배정 관계 등을 명확히 분리해서 설계해주세요. 하나의 주문은 하나의 상태 이력을 계속 쌓아가야 하고, 이전 이력이 수정되거나 삭제되면 안 됩니다.

**17. 기술 요구사항**
Next.js와 TypeScript 기반으로 구현하고, 데이터베이스는 PostgreSQL 계열을 사용해주세요. 결제 기능은 이번 MVP에 포함하지 않습니다(세탁 후 현장 결제).

**18. 테스트**
최소한 다음 흐름은 자동 테스트로 검증해주세요: 고객이 회원가입 후 로그인한다, 주소를 등록한다, 픽업을 요청한다, 관리자가 기사를 배정한다, 기사가 상태를 픽업 완료로 변경한다, 관리자가 세탁 중/세탁 완료로 변경한다, 기사가 배송 중/배송 완료로 변경한다, 고객이 상태 변화를 실시간으로 확인한다, 고객이 픽업 대기 상태의 주문을 취소한다, 이미 픽업 완료된 주문은 고객이 취소할 수 없다, 동일 시간대 중복 요청 시 안내가 표시된다, 다른 고객의 주문에 접근할 수 없다, 배정되지 않은 기사가 다른 기사의 주문에 접근할 수 없다.

**19. 결과물**
전체 소스 코드, 데이터베이스 스키마, 로컬 실행 방법, 환경 변수 예시 파일, 자동 테스트 코드를 포함해주세요. 배포된 Preview URL에서 회원가입부터 픽업 요청, 상태 변경, 배송 완료까지 핵심 흐름을 직접 확인할 수 있어야 합니다.

**20. MVP 제외 범위**
실시간 위치 추적(기사 GPS), 결제 및 정산, 이메일/SMS/푸시 알림, 정기 구독형 반복 픽업 자동화, 다국어 지원, 리뷰·평점 기능은 이번 MVP에서 제외합니다. 가장 중요한 목표는 "픽업 요청 → 기사 배정 → 상태 단계별 진행 → 배송 완료"까지 상태가 정확하고 투명하게 관리되는 것입니다.
