중소기업이 고객 문의를 접수하고 담당자에게 배정하며 처리 이력을 관리할 수 있는 웹 기반 고객지원 티켓 관리 서비스를 구축하고 싶습니다.

현재는 고객 문의가 이메일, 메신저, 전화 등 여러 채널로 들어와 담당자 배정 여부와 처리 상태를 확인하기 어렵습니다. 이번 프로젝트에서는 문의를 하나의 워크스페이스에서 등록하고, 담당자를 배정하고, 답변과 상태 변경 이력을 남길 수 있는 B2B SaaS 형태의 MVP를 개발해 주세요.

주요 사용자는 회사 관리자와 고객지원 담당자입니다. 관리자는 워크스페이스를 생성하고 팀원을 초대하며 전체 문의와 운영 현황을 확인할 수 있어야 합니다. 담당자는 자신에게 배정된 문의를 확인하고 처리 상태를 변경하거나 답변과 내부 메모를 작성할 수 있어야 합니다.

서비스는 반응형 웹으로 구현하며 PC 사용을 우선하되 태블릿과 모바일에서도 핵심 기능을 사용할 수 있어야 합니다.

필수 기능은 다음과 같습니다.

1. 회원가입 및 로그인

사용자는 이메일과 비밀번호로 회원가입하고 로그인할 수 있어야 합니다. 로그인 상태는 새로고침 후에도 유지되어야 하며 로그아웃하면 세션이 종료되어야 합니다. 비밀번호는 안전하게 암호화하여 저장해야 합니다.

비밀번호 재설정 기능을 제공하고, 존재하지 않는 이메일이나 잘못된 비밀번호를 입력한 경우 사용자에게 이해하기 쉬운 오류 메시지를 보여주세요.

2. 워크스페이스 및 팀원 관리

회원가입을 완료한 사용자는 회사명과 워크스페이스 이름을 입력해 워크스페이스를 생성할 수 있어야 합니다.

관리자는 이메일 주소를 이용해 팀원을 초대할 수 있어야 하며, 초대받은 사용자는 초대 링크를 통해 워크스페이스에 참여할 수 있어야 합니다.

사용자 역할은 관리자와 담당자로 구분합니다. 관리자만 팀원 초대, 역할 변경 및 팀원 비활성화를 수행할 수 있어야 합니다. 담당자는 다른 팀원의 권한을 변경할 수 없어야 합니다.

3. 고객 관리

사용자는 고객의 이름, 회사명, 이메일, 전화번호와 메모를 등록하고 수정할 수 있어야 합니다.

고객 목록에서 이름, 회사명 또는 이메일로 검색할 수 있어야 하며, 고객 상세 화면에서는 해당 고객이 요청한 문의 목록과 처리 이력을 확인할 수 있어야 합니다.

동일한 이메일 주소를 가진 고객이 중복 등록되지 않도록 처리해 주세요.

4. 문의 티켓 관리

사용자는 고객 문의를 티켓으로 등록할 수 있어야 합니다. 티켓에는 제목, 문의 내용, 고객, 우선순위, 담당자, 상태와 첨부파일을 포함할 수 있어야 합니다.

티켓 상태는 최소한 신규, 처리 중, 답변 대기, 해결 완료로 구분합니다. 우선순위는 낮음, 보통, 높음, 긴급으로 구분합니다.

티켓 상세 화면에서는 담당자 변경, 상태 변경, 우선순위 변경, 고객에게 전달할 답변 작성 및 내부 메모 작성이 가능해야 합니다.

고객 답변과 내부 메모는 명확하게 구분되어야 하며, 내부 메모는 고객에게 발송되지 않아야 합니다.

누가 언제 티켓을 생성하고 담당자, 상태 또는 우선순위를 변경했는지 활동 이력으로 남겨주세요. 기존 이력을 수정하거나 삭제해서는 안 됩니다.

5. 티켓 목록 및 검색

전체 티켓과 나에게 배정된 티켓을 구분해서 볼 수 있어야 합니다.

상태, 우선순위, 담당자 및 생성일을 기준으로 필터링할 수 있어야 하며 제목, 고객명 또는 고객 이메일로 검색할 수 있어야 합니다.

필터와 검색 조건을 동시에 적용할 수 있어야 합니다. 목록에서는 티켓 제목, 고객, 상태, 우선순위, 담당자와 마지막 업데이트 시간을 확인할 수 있어야 합니다.

6. 대시보드

관리자는 대시보드에서 전체 티켓 수, 신규 티켓 수, 처리 중인 티켓 수, 해결 완료된 티켓 수와 담당자별 미처리 티켓 수를 확인할 수 있어야 합니다.

최근 생성된 티켓과 긴급 티켓을 바로 확인할 수 있어야 하며, 각 항목을 선택하면 해당 티켓 상세 화면으로 이동해야 합니다.

복잡한 통계 분석이나 사용자 정의 리포트는 이번 MVP 범위에 포함하지 않습니다.

7. 알림

사용자에게 티켓이 새로 배정되거나 자신이 담당하는 티켓에 새로운 답변이 추가되면 서비스 내부 알림을 생성해 주세요.

읽지 않은 알림 개수를 헤더에 표시하고, 사용자가 알림을 읽음 처리할 수 있어야 합니다. 실제 이메일 및 SMS 알림 전송은 이번 MVP에서 제외합니다.

8. 파일 첨부

티켓 생성과 답변 작성 시 이미지 또는 PDF 파일을 첨부할 수 있어야 합니다.

허용하지 않는 파일 형식이나 제한 용량을 초과한 파일은 업로드를 차단하고 이유를 안내해 주세요. 업로드된 파일은 해당 워크스페이스에 권한이 있는 사용자만 열람할 수 있어야 합니다.

9. 권한과 보안

사용자는 자신이 속한 워크스페이스의 데이터만 볼 수 있어야 합니다. URL을 직접 입력하거나 API를 호출하더라도 다른 워크스페이스의 고객, 티켓, 첨부파일 및 팀원 정보에 접근할 수 없어야 합니다.

권한 검사는 화면에서 버튼을 숨기는 방식뿐 아니라 서버에서도 수행해 주세요. 비밀번호, 인증 토큰과 외부 서비스 키가 로그나 화면에 노출되지 않아야 합니다.

10. 오류 및 상태 처리

모든 주요 화면에 로딩, 빈 상태, 오류 및 재시도 경험을 제공해 주세요.

네트워크 요청 실패 시 사용자가 작성 중인 답변이 사라지지 않아야 하며, 저장 버튼을 여러 번 눌러도 같은 답변이나 티켓이 중복 생성되지 않도록 처리해 주세요.

기술 요구사항은 Next.js와 TypeScript 기반 웹 애플리케이션, Node.js 서버 환경 및 PostgreSQL 데이터베이스입니다. 정확한 라이브러리는 개발자가 제안할 수 있지만 장기적으로 유지보수할 수 있는 안정적인 기술을 우선해 주세요.

결과물에는 전체 소스 코드, 데이터베이스 스키마와 마이그레이션, 테스트용 합성 데이터, 환경 변수 예시, 로컬 실행 방법, 배포 방법 및 관리자용 기본 사용 안내가 포함되어야 합니다.

핵심 사용자 흐름은 자동 테스트로 검증할 수 있어야 합니다. 최소한 다음 흐름을 Playwright로 테스트해 주세요.

- 관리자가 회원가입 후 워크스페이스를 생성한다.
- 관리자가 담당자를 초대한다.
- 담당자가 초대를 수락하고 로그인한다.
- 고객을 등록하고 해당 고객의 문의 티켓을 생성한다.
- 관리자가 티켓을 담당자에게 배정한다.
- 담당자가 티켓 상태를 처리 중으로 변경하고 답변을 작성한다.
- 담당자가 티켓을 해결 완료 상태로 변경한다.
- 권한이 없는 사용자가 다른 워크스페이스의 티켓에 접근하지 못한다.

배포된 Preview URL에서 전체 흐름을 직접 확인할 수 있어야 합니다. 기능별 완료 여부는 승인된 완료조건과 특정 Commit SHA를 기준으로 검수할 예정입니다.

이번 MVP에서는 실시간 채팅, 전화 연동, 외부 이메일 수신, SMS 발송, AI 자동 답변, 다국어 지원, 결제 및 구독, 고급 통계 리포트와 모바일 앱은 제외합니다.

[예시 1] 이커머스/물류 분야: B2B 재고 및 발주 관리 시스템 MVP

중소규모 유통업체가 다수의 창고 재고를 실시간으로 파악하고 공급업체에 발주를 진행하며 입출고 이력을 관리할 수 있는 웹 기반 재고/발주 관리 서비스를 구축하고 싶습니다.

현재는 각 창고의 재고 현황을 엑셀이나 수기 장부로 분산 관리하고 있어, 실시간 재고 파악이 지연되고 품절이나 과잉 재고 문제가 빈번하게 발생하고 있습니다. 또한 공급업체에 보내는 발주서(PO)를 이메일이나 메신저로 개별 전송하다 보니 담당자 부재 시 업무가 마비되고 입고 지연이나 승인 누락 여부를 확인하기 어렵습니다. 이번 프로젝트에서는 하나의 통합된 워크스페이스에서 상품 및 창고를 등록하고, 안전 재고 미달 시 발주서를 생성하며, 입출고 흐름과 재고 상태를 체계적으로 관리할 수 있는 B2B SaaS 형태의 MVP를 개발해 주세요.

주요 사용자는 회사 내 창고 관리자(Admin)와 발주 담당자(Agent)입니다. 관리자는 전체 창고 현황과 발주 승인 권한을 가지며, 담당자는 입출고 처리 및 발주서 기안을 담당합니다. 서비스는 반응형 웹으로 구현하며 현장 작업자를 위해 태블릿 환경에서도 원활하게 동작해야 합니다.

필수 기능은 다음과 같습니다.

1. 회원가입 및 로그인
사용자는 이메일과 비밀번호로 회원가입하고 로그인할 수 있어야 합니다. 보안을 위해 비밀번호는 암호화하여 저장하며, 세션 관리 및 비밀번호 재설정 기능을 제공합니다.

2. 창고 및 팀원 관리
회원가입을 완료한 관리자는 회사(워크스페이스)를 생성하고 하위 물리적 창고(Location)를 다수 등록할 수 있습니다. 이메일 초대를 통해 팀원을 추가하며, 관리자와 일반 담당자로 권한을 엄격히 구분합니다.

3. 상품(SKU) 관리
취급하는 상품명, 고유 바코드 넘버, 카테고리, 안전 재고량, 매입 단가를 등록하고 수정할 수 있어야 합니다. 동일한 바코드 번호가 중복 등록되지 않도록 유효성 검사를 적용해 주세요.

4. 재고 및 발주 관리 (핵심 워크플로우)
특정 상품의 재고가 안전 재고량 이하로 떨어지면 시스템이 발주 필요 상태로 표시합니다. 담당자는 공급업체를 지정하여 발주서(PO)를 생성(기안)하고, 관리자가 이를 승인하면 '입고 대기' 상태로 전환됩니다. 실제 물건이 도착하면 담당자가 '입고 완료' 처리를 하여 재고 수량을 증가시킵니다.
또한 일반적인 출고(판매) 및 불량/반품에 의한 재고 차감 로직도 지원해야 합니다.

5. 검색 및 필터링
상품명이나 바코드로 특정 상품의 현재고를 즉시 검색할 수 있어야 합니다. 카테고리별 필터 및 '재고 부족' 상태 필터를 동시에 적용하여 위험 재고를 빠르게 파악할 수 있어야 합니다.

6. 대시보드
관리자는 대시보드에서 전체 창고의 총 재고 자산 규모, 안전 재고 미달 상품 수, 금주 입고 예정인 발주 건수를 위젯 형태로 한눈에 확인할 수 있어야 합니다.

7. 알림 및 파일 첨부
새로운 발주서가 상신되거나 승인/반려되었을 때, 그리고 특정 상품이 품절 임박 상태가 되었을 때 서비스 내부 알림을 발송합니다. 발주서 생성 시 공급업체에서 받은 견적서(PDF)나 상품 이미지를 첨부할 수 있어야 합니다.

8. 권한과 보안 및 예외 처리
본인이 속한 워크스페이스의 데이터만 열람/수정 가능해야 하며, API 호출 시에도 엄격한 권한 검증을 거쳐야 합니다. 다수의 담당자가 동시에 입출고 처리를 할 때 재고 수량 충돌(Race Condition)이 발생하지 않도록 DB 트랜잭션 처리를 보장해 주세요.

기술 요구사항: Next.js, TypeScript 기반의 반응형 웹과 Node.js 서버, PostgreSQL 데이터베이스 환경.
결과물: 소스 코드, DB 스키마, 환경변수 예시, 배포 가이드.
핵심 테스트 (Playwright): 관리자 창고 생성 -> 담당자 초대 -> 상품 등록 -> 발주서 기안 및 관리자 승인 -> 입고 완료 처리 후 재고 증가 확인.
MVP 제외 범위: 물류사 API 연동(실시간 배송 추적), 바코드 스캐너 하드웨어 연동, 외부 ERP(SAP 등) 데이터 자동 동기화.

[예시 2] HR/인사 분야: 사내 근태 및 휴가 관리 시스템 MVP

스타트업 및 중소기업이 임직원의 출퇴근 기록을 정확히 수집하고, 휴가(연차) 신청 및 결재 이력을 체계적으로 관리할 수 있는 웹 기반 HR 서비스를 구축하고 싶습니다.

현재는 직원들의 출퇴근 관리를 슬랙(Slack) 메시지나 구글 폼으로 대체하고 있으며, 휴가 신청 역시 이메일과 구두로 이루어지고 있습니다. 이로 인해 인사 담당자가 매월 말 직원별 잔여 연차를 수동으로 계산해야 하며, 관리자는 오늘 누가 휴가이고 누가 재택근무 중인지 파악하기 어렵습니다. 이번 프로젝트에서는 임직원들이 자신의 근태를 직접 기록하고 휴가를 신청하며, 관리자는 부서별 근태 현황과 결재 라인을 일원화하여 관리할 수 있는 B2B SaaS 형태의 MVP를 개발해 주세요.

주요 사용자는 인사 관리자(Admin)와 일반 임직원(Employee)입니다. 모바일 웹 환경에서도 출퇴근 체크와 휴가 신청이 매우 직관적이고 빠르게 이루어져야 합니다.

필수 기능은 다음과 같습니다.

1. 회원가입 및 조직 관리
최초 가입한 인사 관리자는 회사 워크스페이스를 생성하고 사내 부서(팀) 트리를 구성할 수 있습니다. 이메일을 통해 사원을 초대하며, 초대된 직원은 비밀번호를 설정하고 가입을 완료합니다.

2. 임직원 프로필 및 연차 관리
사원별 기본 정보(이름, 입사일, 비상 연락처 등)를 관리합니다. 관리자는 사원의 입사일을 기준으로 총 부여된 연차 일수를 등록 및 수정할 수 있으며, 시스템은 사용된 휴가를 차감하여 '잔여 연차'를 자동으로 계산해야 합니다.

3. 근태 기록 (출퇴근 체크)
직원은 메인 화면에서 '출근'과 '퇴근' 버튼을 클릭하여 서버의 현재 시간 기준으로 기록을 남깁니다. 하루에 한 번만 출퇴근 기록이 가능하며, 관리자는 전체 직원의 출퇴근 기록을 열람하고 지각/조기퇴근 여부를 확인할 수 있습니다. 사후에 누락된 기록에 대해 관리자가 사유(메모)를 입력하고 수동으로 수정할 수 있는 기능이 필요합니다.

4. 휴가 신청 및 전자결재 워크플로우
직원은 휴가 종류(연차, 반차, 병가, 공가 등), 시작/종료일, 사유를 입력하여 휴가를 상신합니다. 상신된 휴가는 해당 부서의 관리자에게 전달되며, 관리자는 이를 승인(Approved)하거나 반려(Rejected)할 수 있습니다. 승인 시 잔여 연차가 즉시 차감됩니다.

5. 조회 및 검색 필터
직원은 본인의 과거 휴가 신청 내역과 상태, 근태 기록만 조회할 수 있습니다. 관리자는 전체 직원의 기록을 부서별, 날짜별(월간), 상태별(승인/대기)로 필터링하여 검색할 수 있어야 합니다.

6. 대시보드 및 알림
관리자 대시보드에서는 오늘 휴가자 목록, 결근/지각자 현황, 결재를 기다리는 휴가 신청 건수를 한눈에 볼 수 있어야 합니다. 휴가가 승인되거나 반려되었을 때 기안자에게 즉각적인 서비스 내부 알림을 제공합니다.

7. 파일 첨부 및 보안
병가나 예비군 훈련 등 증빙이 필요한 휴가 신청 시 진단서나 통지서 파일(이미지, PDF)을 첨부할 수 있어야 합니다. 첨부파일은 관리자와 본인만 열람 가능하도록 보안 처리해야 합니다.

기술 요구사항: Next.js, TypeScript, Node.js, PostgreSQL.
결과물: 소스 코드, DB 스키마, 테스트 데이터베이스 세팅 가이드.
핵심 테스트 (Playwright): 워크스페이스 및 부서 생성 -> 직원 초대 및 로그인 -> 직원의 출퇴근 버튼 클릭 -> 직원의 연차 신청 -> 관리자 로그인 후 연차 승인 -> 직원의 잔여 연차 차감 확인.
MVP 제외 범위: 복잡한 급여(Payroll) 자동 정산, 지문/안면 인식 등 외부 하드웨어 출입 단말기 연동, 법정 의무교육 수강 관리 기능.

[예시 3] 에듀테크 분야: B2B 사내 교육 및 과제 관리 (LMS) MVP

기업이 신규 입사자 온보딩이나 직무별 필수 교육을 위해 온라인 강의 클래스를 개설하고, 수강생의 진도율과 과제 제출 이력을 체계적으로 관리할 수 있는 학습 관리 시스템(LMS) MVP를 구축하고 싶습니다.

현재는 사내 교육 자료(비디오 링크, PDF 등)를 사내 인트라넷 게시판이나 메신저로 일방적으로 배포하고 있습니다. 이로 인해 누가 어떤 교육을 완료했는지, 과제는 제대로 수행했는지 추적할 수 없어 교육 담당자가 일일이 수합하고 독촉해야 하는 실정입니다. 이번 프로젝트에서는 클래스를 개설하여 커리큘럼을 등록하고, 수강생을 초대하여 진도율을 자동 측정하며, 과제 제출 및 강사 피드백을 단일 공간에서 주고받을 수 있는 MVP를 개발해 주세요.

주요 사용자는 교육 담당자/강사(Admin/Instructor)와 수강생(Student)입니다. 

필수 기능은 다음과 같습니다.

1. 회원가입 및 클래스 관리
회사 관리자는 워크스페이스를 생성한 뒤, 다수의 교육 클래스(예: 2024 신규 입사자 온보딩, 영업 직무 심화 교육 등)를 개설할 수 있습니다. 각 클래스에 교육 담당자(강사)와 수강생을 이메일로 초대하여 배정합니다.

2. 커리큘럼 구성 및 콘텐츠 등록
강사는 클래스 내부에 주차별(또는 모듈별) 챕터를 생성할 수 있습니다. 각 챕터에는 텍스트 설명, 외부 동영상 링크(YouTube 또는 Vimeo 임베드), 참고용 첨부파일을 등록하여 학습 커리큘럼을 구성합니다.

3. 진도율 트래킹
수강생이 각 강의 콘텐츠(동영상 조회, 텍스트 읽음 확인 버튼 등)를 완료할 때마다 해당 클래스의 전체 진도율(%)이 갱신됩니다. 수강생은 자신의 진도율을 직관적인 프로그레스 바 형태로 확인할 수 있습니다.

4. 과제 제출 및 피드백 (핵심 로직)
강사는 특정 챕터에 과제를 생성할 수 있습니다(주관식 텍스트 입력 또는 파일 제출 형태). 수강생이 과제를 제출하면 강사에게 알림이 가며, 강사는 제출물을 확인 후 점수(Pass/Fail)와 텍스트 피드백을 남길 수 있습니다. 강사의 피드백이 등록되면 수강생은 수정 후 재제출을 할 수도 있습니다.

5. 수강생 현황 및 필터링
강사는 클래스 내 전체 수강생 목록을 보고 이름 및 부서로 검색할 수 있습니다. 특히 진도율이 50% 미만인 수강생이나 미제출 과제가 있는 수강생만 필터링하여 확인하는 기능이 필수적입니다.

6. 대시보드
교육 담당자 대시보드에서는 현재 운영 중인 전체 클래스 수, 클래스별 평균 수강 완료율, 평가 대기 중인 과제 수 등을 시각적으로 보여줍니다. 

7. 파일 처리 및 접근 권한
수강생은 과제 제출 시 문서(PDF, Word)나 압축 파일(ZIP)을 업로드할 수 있으며 용량 제한(예: 20MB)을 두어야 합니다. 수강생은 본인의 과제물과 피드백만 볼 수 있으며, 다른 수강생의 과제는 절대 조회할 수 없도록 권한을 분리해야 합니다.

기술 요구사항: Next.js, TypeScript, Node.js, PostgreSQL.
결과물: 전체 소스 코드, DB 스키마/마이그레이션, 실행 가이드.
핵심 테스트 (Playwright): 강사가 클래스 및 주차별 강의 생성 -> 수강생 초대 -> 수강생이 콘텐츠 열람 후 과제(파일) 제출 -> 강사가 과제 확인 후 Pass 처리 및 피드백 작성 -> 수강생의 진도율 증가 확인.
MVP 제외 범위: 실시간 화상 강의(Zoom) API 내장, 무거운 영상 파일의 직접 스트리밍 서버 구축, 유료 강의 결제 및 PG사 연동.

[예시 4] 프롭테크 분야: 상업용 부동산 매물 및 임대차 계약 관리 MVP

부동산 중개 법인이 다수의 상업용 부동산 매물을 상세하게 등록하고, 임차를 희망하는 고객의 응대 이력부터 최종 임대차 계약까지의 진행 상태를 체계적으로 트래킹할 수 있는 CRM 플랫폼을 구축하고 싶습니다.

현재 소속 중개인들은 각자 수집한 매물 정보와 고객 연락처를 개인 수첩이나 개별 엑셀 파일로 관리하고 있습니다. 이로 인해 우수한 매물 정보가 법인 내부에 자산화되지 않으며, 한 고객에게 여러 중개인이 중복 연락을 하거나 특정 매물의 계약 진행 상태(공실, 가계약 등)를 실시간으로 공유받지 못해 영업 차질이 발생합니다. 이번 프로젝트에서는 통합된 워크스페이스에서 매물 DB를 구축하고, 고객 문의를 기록하며, 매물-고객 간의 계약 워크플로우를 가시화할 수 있는 B2B SaaS 형태의 MVP를 개발해 주세요.

주요 사용자는 중개 법인의 관리자(Admin)와 소속 중개인(Agent)입니다. 

필수 기능은 다음과 같습니다.

1. 회원가입 및 팀원 관리
중개 법인 명의로 워크스페이스를 생성하고 소속 중개인들을 초대합니다. 관리자는 중개인들의 접근 권한을 관리하며 비활성화 처리할 수 있어야 합니다.

2. 매물(Listing) 관리
중개인은 새로운 매물을 시스템에 등록할 수 있습니다. 필수 입력 정보로는 건물명, 상세 주소, 면적(평수), 보증금/월세/관리비, 층수, 그리고 현재 매물 상태(공실, 투어 진행 중, 가계약, 최종 계약 완료)가 포함되어야 합니다. 주소 입력 시 카카오/구글 지도 API 텍스트 연동 등을 통해 정확한 위치 값을 저장하는 것이 좋습니다.

3. 고객 및 영업 이력 트래킹
임차 희망 고객의 기본 정보(이름, 연락처, 희망 예산, 선호 지역 등)를 등록합니다. 고객과 통화하거나 미팅한 내역을 타임라인 형태의 메모로 남길 수 있어야 하며, 동료 중개인이 해당 고객의 이전 상담 이력을 바로 파악할 수 있어야 합니다.

4. 매물-고객 매핑 및 계약 상태 관리
특정 매물에 관심 있는 고객을 매핑(연결)하여 계약 진행 파이프라인(문의 접수 -> 매물 투어 -> 가격 협상 -> 가계약 -> 최종 계약)을 관리할 수 있어야 합니다. 매물이 최종 계약 상태로 변경되면, 다른 중개인들에게 해당 매물이 더 이상 공실이 아님을 즉각 표시해야 합니다.

5. 상세 검색 및 필터링
수많은 매물 중에서 면적(범위 지정), 가격대(보증금/월세), 특정 지역, 매물 상태를 기준으로 교집합 필터링을 수행할 수 있어야 합니다. 

6. 대시보드
관리자 대시보드에서는 현재 확보된 공실 매물 수, 이번 달 계약 완료 건수, 소속 중개인별 영업 활동 현황(등록한 매물 수, 성사시킨 계약 수)을 통계치로 확인할 수 있어야 합니다.

7. 파일 첨부 및 보안 권한
매물 등록 시 내/외부 사진 이미지와 건축물대장 스캔본 등을 첨부할 수 있어야 합니다. 임대인(건물주)의 연락처나 민감한 임대차 계약서 파일은 해당 워크스페이스 내에서도 권한을 부여받은 관리자나 담당 중개인만 열람할 수 있도록 보안 처리가 강력해야 합니다.

기술 요구사항: Next.js, TypeScript, Node.js, PostgreSQL.
결과물: 소스 코드, 테스트용 합성 데이터 세트, 로컬 실행 및 배포 방법 안내.
핵심 테스트 (Playwright): 법인 워크스페이스 생성 및 중개인 초대 -> 중개인이 공실 매물 등록 -> 임차 희망 고객 등록 -> 특정 매물에 고객을 매핑하여 상태를 '투어 진행 중'에서 '최종 계약'으로 변경 -> 매물 상태가 공실에서 제외되는지 확인.
MVP 제외 범위: 국토교통부 실거래가 및 공공데이터 자동 크롤링 연동, 정식 전자서명 기능(법적 효력 있는 계약서 서명), 임대료 자동 수납을 위한 결제 게이트웨이 연동.
