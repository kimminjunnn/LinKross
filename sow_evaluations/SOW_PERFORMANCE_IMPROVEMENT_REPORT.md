# LinKross AI 모델 SOW 생성 성능 향상 리포트

## 1. 개요 및 배경
본 문서는 기존 AI 모델이 업무 명세서(SOW)를 생성할 때 발생했던 품질적 한계를 분석하고, 이를 극복하기 위한 **성능 향상 프로세스(약점 진단 ➡️ 프롬프트 엔지니어링 ➡️ 지표 상승 결과)**를 기록한 리포트입니다. 
모델의 지능은 이미 훌륭했으나, '출력의 방향성(목적 함수)'을 바로잡음으로써 **자동화 검수(Playwright E2E 테스트)가 즉시 가능한 100% 수준**으로 성능을 끌어올린 전 과정을 담고 있습니다.

---

## 2. 약점 파악 (문제 진단)
`SOW_PROMPT_FEEDBACK.md` 분석 결과, 기존 AI 산출물은 다음과 같은 5가지 치명적인 구조적 오류(약점)를 반복하고 있었습니다.

1. **기술 레이어 중심의 분할 및 기술 용어 남발:** 사용자 행동(화면) 기준이 아닌, 개발자의 작업 순서(DB 설계 ➡️ API ➡️ UI)대로 마일스톤을 잡음. 비개발 발주자는 검증 불가능함.
2. **과도한 뭉뚱그리기 (마일스톤 수 감소):** 7단계로 나눠야 할 작업을 3~4개로 뭉쳐서 처리하여 테스트 단위를 비대하게 만듦.
3. **엣지 케이스 누락 및 병합:** '이름 누락'과 '증상 누락' 등 별도로 테스트해야 할 조건들을 하나의 문장으로 합쳐버려 검수 커버리지를 떨어뜨림.
4. **UI 라우팅(URL) 부재:** "마이페이지", "목록 화면" 등 추상적인 한글 명사를 사용하여 자동화 봇이 이동할 목적지를 알 수 없음.
5. **모호한 서술 및 행위 서술:** 구체적 에러 문구나 버튼 변화 대신 "~반영된다", "~할 수 있다"는 모호한 표현을 쓰거나, DoD에 "QA 테스트 수행" 같은 검증 불가능한 행위 자체를 서술함.

---

## 3. 성능 보완 및 솔루션 적용 (프롬프트 고도화)
파악된 5대 약점을 보완하기 위해, 모델에 주입하는 **시스템 프롬프트(System Prompt) 가이드라인**을 새롭게 재설계했습니다. 모델의 자율성을 제한하고 기계적인 규칙을 강제하는 방식으로 보완했습니다.

* 💡 **솔루션 1: 화면 단위 분할 강제 (기술 용어 차단)**
  * 조치: 마일스톤 제목에 "DB", "아키텍처", "API" 등의 백엔드/인프라 용어 사용을 전면 금지하고, 무조건 '비개발자가 브라우저에서 관찰할 수 있는 화면/기능' 기준으로 분할하도록 강제함.
* 💡 **솔루션 2: 7단계 마이크로 마일스톤 강제**
  * 조치: 마일스톤을 뭉뚱그리지 않도록 최소 5~7개의 마일스톤으로 나누고, 핵심기능/제한기능/예외처리를 분리하도록 지시함.
* 💡 **솔루션 3: 조건별 독립적 DoD 분리 (엣지 케이스 고립)**
  * 조치: 성공 케이스와 실패 케이스, A조건과 B조건을 하나의 문장으로 합치는 것을 금지하고, 반드시 개별 DoD 항목으로 나누어 작성하도록 강제함.
* 💡 **솔루션 4: 예상 URL 명시 100% 적용**
  * 조치: 행동이 일어나는 위치와 목적지를 `/login`, `/admin/classes` 등의 정확한 URL 형태로 표기하는 것을 필수화함.
* 💡 **솔루션 5: 관찰 가능한 GIVEN-WHEN-THEN 상태 변화 묘사**
  * 조치: "~된다"식 표현을 금지하고, **버튼 텍스트 변화, 숫자 증감, 정확한 에러 문구 노출** 등 눈으로 확인 가능한 UI 컴포넌트의 변화만 서술하도록 규칙 추가.

* 특히 기술 용어 사용을 차단하고 사용자 화면 중심으로 사고를 전환시킴으로써, **발주자와 프리랜서 간의 인식 차이를 줄이는 LinKross 본연의 목적**을 달성했습니다.
