# 성능 테스트 시나리오 6: 인스타그램 릴스 장소 북마크 서비스

기존 5개 골드스탠다드 시나리오(`SOW_5_EXAMPLES.md`)보다 기능 범위가 넓고(인증+외부 콘텐츠 처리+지도+리스트+검색+초대+관리자), 다대다 관계(Reel↔Place, List↔Place)와 비동기 처리 상태(추출 대기/중/성공/실패)가 섞여 있어 SOW 자동 생성 성능을 스트레스 테스트하기 좋은 케이스입니다.

이 문서는 `src/app/actions/analyze.ts`의 현재 필수 규칙(마일스톤 5~7개, 화면 단위 분할, 엣지 케이스 개별 DoD 분리, URL 명시, 명사형 종결)을 기준으로 작성한 **예상(Gold Standard) 마일스톤·DoD**입니다. 실제 LinKross SOW 생성 화면에 아래 [입력 프롬프트]를 넣고 나온 AI 결과를 이 문서와 대조해서 성능을 확인하면 됩니다.

## 🎯 예상 마일스톤 & DoD (Gold Standard)

### M1: 회원가입/로그인/세션 관리
- DoD: `/signup`에서 이메일·비밀번호 입력 후 가입 완료 시 `/login`으로 이동됨
- DoD: `/login`에서 올바른 이메일·비밀번호 입력 후 로그인 성공 시 `/reels`로 이동됨
- DoD: `/login`에서 존재하지 않는 이메일 입력 시 "가입되지 않은 계정입니다" 오류 메시지가 표시됨
- DoD: `/login`에서 비밀번호를 틀리게 입력 시 "비밀번호가 일치하지 않습니다" 오류 메시지가 표시됨
- DoD: 로그인 상태에서 새로고침 시 세션이 유지되어 `/reels` 화면이 그대로 표시됨
- DoD: 로그아웃 버튼 클릭 시 세션이 종료되고 `/login`으로 이동됨
- DoD: 비로그인 상태에서 `/reels` 접근 시 `/login`으로 리다이렉트됨
- DoD: 비밀번호 입력값이 화면 및 브라우저 콘솔에 평문으로 노출되지 않음 확인

### M2: 릴스 등록 및 분석 상태 관리
- DoD: `/reels/new`에서 인스타그램 릴스 URL 입력 후 등록 클릭 시 `/reels` 목록에 새 항목이 추가됨
- DoD: 등록 직후 해당 릴스 항목의 상태 배지가 "분석 대기" 또는 "분석 중"으로 표시됨
- DoD: 이미 본인이 등록한 릴스 URL을 재등록 시도 시 "이미 저장한 릴스입니다" 안내가 표시되고 중복 항목이 생성되지 않음 확인
- DoD: 분석이 진행 중인 릴스 항목에 로딩 인디케이터가 표시됨
- DoD: 장소 추출 성공 시 릴스 항목 상태 배지가 "추출 성공"으로 변경됨
- DoD: 장소 추출 실패 시 릴스 항목 상태 배지가 "추출 실패"로 변경됨
- DoD: "추출 실패" 상태의 `/reels/[id]`에서 "다시 시도" 클릭 시 상태가 "분석 중"으로 변경됨
- DoD: 장소 추출 결과가 없는 릴스도 `/reels` 목록에서 계속 조회됨 확인

### M3: 릴스 장소 추출 결과 확인
- DoD: `/reels/[id]`에서 장소가 정상 추출된 경우 장소명·주소·카테고리·썸네일이 카드로 표시됨
- DoD: 하나의 릴스에서 복수 장소가 확인된 경우 `/reels/[id]`에 장소 후보 카드가 여러 개 나열됨
- DoD: 장소를 특정할 수 없는 경우 `/reels/[id]`에 "장소를 찾지 못했습니다" 안내가 표시되고 임의의 장소가 저장되지 않음 확인
- DoD: 장소 후보 카드에서 "내 장소로 저장" 클릭 시 해당 장소가 `/places` 목록에 추가됨

### M4: 지도 기반 장소 확인
- DoD: `/map` 접속 시 본인이 저장한 장소만 위도·경도 기준 핀으로 표시됨
- DoD: 다른 사용자가 저장한 장소는 `/map`에 표시되지 않음 확인
- DoD: 지도 핀 클릭 시 장소명·카테고리·주소·연결된 릴스·소속 리스트가 포함된 상세 팝업이 표시됨
- DoD: 상세 팝업에서 "상세 보기" 클릭 시 `/places/[id]`로 이동됨
- DoD: `/map`의 장소 목록에서 특정 장소 선택 시 지도에서 해당 핀이 강조 표시됨
- DoD: 지도에서 핀 선택 시 함께 노출된 목록에서 해당 장소 항목이 선택 상태로 표시됨

### M5: 저장 장소 목록·검색·상세·메모
- DoD: `/places` 접속 시 저장한 장소의 장소명·카테고리·주소·저장 시간이 목록으로 표시됨
- DoD: `/places`에서 장소명 키워드 검색 시 일치하는 장소만 목록에 표시됨
- DoD: `/places` 목록에서 장소 선택 시 `/places/[id]`로 이동됨
- DoD: `/places/[id]`에서 장소명·주소·카테고리·지도 위치·연결된 릴스·소속 리스트가 표시됨
- DoD: `/places/[id]`에서 메모 입력 후 저장 시 작성한 메모 내용이 화면에 그대로 표시됨
- DoD: `/places/[id]`에서 기존 메모 수정 후 저장 시 변경된 메모 내용으로 갱신됨
- DoD: 동일 장소가 여러 릴스에서 추출된 경우 `/places/[id]`에 연결된 릴스가 장소 중복 생성 없이 여러 건 함께 표시됨 확인

### M6: 리스트/컬렉션 관리 및 직접 장소 검색
- DoD: `/lists`에서 "새 리스트 만들기" 클릭 후 이름 입력 시 `/lists` 목록에 새 리스트가 추가됨
- DoD: 장소 상세 또는 장소 카드에서 리스트 추가 클릭 시 선택한 장소가 해당 리스트에 추가됨
- DoD: `/lists/[id]`에서 장소 제거 클릭 시 해당 장소가 리스트에서 제거됨
- DoD: `/lists/[id]`에서 리스트에 포함된 장소 선택 시 `/places/[id]`로 이동됨
- DoD: `/lists/[id]`에서 리스트 이름 수정 후 저장 시 변경된 이름이 `/lists` 목록에 반영됨
- DoD: `/lists/[id]`에서 리스트 삭제 시 해당 리스트가 `/lists` 목록에서 사라지고, 포함되어 있던 장소는 `/places` 목록에서 계속 조회됨 확인
- DoD: `/search`에서 장소명 키워드 검색 시 장소명·주소·카테고리·위치가 포함된 검색 결과가 표시됨
- DoD: `/search` 검색 결과에서 "저장하기" 클릭 시 해당 장소가 `/places` 목록에 추가됨
- DoD: `/search` 검색 결과 중 이미 저장된 장소에는 "저장됨" 표시가 나타나고 중복 저장되지 않음 확인

### M7: 친구 초대 및 관리자 페이지
- DoD: `/invite`에서 초대 링크 생성 클릭 시 초대 링크가 화면에 표시됨
- DoD: 발급된 초대 링크로 접속 시 회원가입 또는 로그인 화면으로 이동됨
- DoD: 일반 사용자 계정으로 `/admin` 접속 시 접근이 차단되고 권한 없음 안내가 표시됨
- DoD: 관리자 계정으로 `/admin` 접속 시 신규 가입자 수·릴스 저장 수·장소 저장 수·추출 성공률이 대시보드에 표시됨
- DoD: `/admin/users`에서 이메일 또는 이름으로 검색 시 일치하는 사용자만 목록에 표시됨
- DoD: `/admin/users/[id]`에서 해당 사용자의 가입 일시·저장한 릴스·저장한 장소·생성한 리스트가 표시됨
- DoD: `/admin/users/[id]`에서 "이용 정지" 클릭 시 사용자 상태가 "정지"로 변경되고 사용자 데이터는 삭제되지 않음 확인
- DoD: `/admin/reels`에서 "추출 실패" 상태의 릴스만 별도로 필터링되어 표시됨
- DoD: 사용자 A 계정에서 API 또는 URL로 사용자 B의 `/places` 데이터에 접근 시도 시 조회가 차단됨 확인

## 대조 시 체크포인트

실제 AI 생성 결과와 비교할 때 특히 아래 항목에서 기존 모델이 취약했던 패턴(`SOW_PERFORMANCE_METRICS.md` 참고)이 재현되는지 확인하세요.

1. **마일스톤 개수** — 5~7개를 지키는지, 아니면 뭉뚱그려 3~4개로 압축하는지
2. **기술 용어 유입 여부** — "DB 스키마 설계", "ExtractionJob 큐 구현" 같은 백엔드 관점 마일스톤이 등장하는지 (본 시나리오는 §16 데이터 구조에 엔티티명이 노출되어 있어 특히 새어나오기 쉬운 케이스)
3. **비동기 상태(분석 대기/중/성공/실패) 처리** — 4가지 상태 전환을 각각 개별 DoD로 쪼갰는지, 아니면 "분석 상태가 표시된다" 식으로 뭉쳤는지
4. **다대다 관계 처리(M3, M5)** — "동일 장소 여러 릴스 연결", "장소 중복 생성 방지"를 정확히 짚었는지
5. **권한 경계(M4, M7)** — "다른 사용자 장소 미노출", "타 사용자 데이터 접근 차단"이 개별 DoD로 나왔는지
6. **명사형 종결 준수율** — "~된다/한다"가 섞여 나오면 §21.3 규칙이 실제로는 100% 강제되지 않는다는 신호
