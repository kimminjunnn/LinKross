# LinKross SOW 생성 테스트용 5대 시나리오 (프롬프트 & 모범 마일스톤)

본 문서는 업무 명세서(SOW) 자동 생성 프롬프트 및 AI 모델의 성능을 테스트하기 위한 5가지 실무 시나리오(요구사항 프롬프트)와 각각의 모범 마일스톤(Gold Standard)을 정리한 데이터셋입니다.

---

## 1. 헬스장 PT 예약 관리 서비스

### 📝 [업무 상세 프롬프트 (요구사항)]
동네에서 소규모 헬스장을 운영하고 있는데, PT 예약을 전부 카카오톡이랑 종이 다이어리로 관리하다 보니 문제가 많습니다. 같은 시간에 두 명이 예약해서 겹치는 일이 생기고, 노쇼가 나도 기록이 안 남아서 다음에 또 같은 일이 반복됩니다. 트레이너마다 자기 스케줄을 따로 관리하다 보니 저도 전체 현황을 파악하려면 트레이너들한테 일일이 물어봐야 합니다. 회원이 앱에서 직접 트레이너와 시간을 골라 예약하고, 트레이너와 저는 예약 현황을 한눈에 볼 수 있는 웹 서비스를 만들고 싶습니다.
회원은 회원가입 후 로그인해서 트레이너 목록을 봅니다. 각 트레이너마다 소개, 전문 분야, 이번 주 가능한 시간대가 나와야 합니다. 회원이 원하는 시간을 골라 예약하면 확정되고, 같은 시간에 다른 사람이 이미 예약했다면 그 시간은 선택할 수 없어야 합니다. 예약 확정 후에는 회원 마이페이지와 트레이너 스케줄 화면 양쪽에 반영되어야 합니다.
회원은 예약 목록에서 다가오는 예약과 지난 예약을 구분해서 볼 수 있어야 하고, 예약을 취소할 수 있어야 합니다. 다만 예약 시간 몇 시간 전부터는 취소가 안 되게 막고 싶은데, 이건 MVP에서는 단순하게 "취소는 언제든 가능"으로 시작해도 됩니다. 취소되면 그 시간 슬롯은 다시 다른 회원이 예약할 수 있게 열려야 합니다.
트레이너는 별도 계정으로 로그인해서 자기 스케줄만 볼 수 있어야 하고, 다른 트레이너의 예약 정보는 볼 수 없어야 합니다. 트레이너 화면에는 오늘 예약, 이번 주 예약이 시간순으로 정리되어 보이면 좋겠습니다.
저(관리자)는 전체 회원 목록, 전체 트레이너 목록, 오늘 하루 전체 예약 현황을 한 화면에서 볼 수 있어야 합니다. 필요하면 관리자가 특정 예약을 강제로 취소할 수 있는 기능도 있으면 좋겠습니다. 노쇼가 잦은 회원을 파악할 수 있도록 예약 취소/노쇼 이력을 남기는 것도 고려해주세요.
기술은 Next.js 기반으로 하고 싶고, 회원이 예약하는 화면은 모바일에서 특히 편해야 합니다. PT 비용 결제나 정산 기능은 이번엔 빼고, 예약이 겹치지 않고 정확하게 관리되는 것부터 확실히 만들어주세요.

### 🎯 [모범 마일스톤 & DoD]
- **M1: 회원 가입/로그인/로그아웃**
    - DoD: `/signup`에서 이메일·비밀번호 입력 후 가입 시 `/login`으로 이동한다.
    - DoD: 로그인 성공 시 `/dashboard`로 이동하고, 잘못된 비밀번호 입력 시 에러 메시지가 표시된다.
    - DoD: 로그아웃 클릭 시 `/login`으로 이동하고, 이후 `/dashboard` 접속 시 다시 `/login`으로 리다이렉트된다.
- **M2: 트레이너 목록 및 상세 조회**
    - DoD: `/trainers`에 트레이너 카드 목록이 표시되고, 카드 클릭 시 `/trainers/[id]`로 이동한다.
    - DoD: `/trainers/[id]`에 예약 가능한 시간 슬롯이 버튼 형태로 표시된다.
- **M3: 예약 생성 및 중복 방지**
    - DoD: 시간 슬롯 클릭 후 예약 확정 시 `/my-reservations`에 해당 예약이 목록에 나타난다.
    - DoD: 이미 예약된 시간 슬롯은 클릭이 비활성화되거나 선택 시 "이미 예약된 시간입니다" 에러가 표시된다.
    - DoD: 예약 완료 직후 트레이너 스케줄 화면에서도 동일한 예약이 조회된다.
- **M4: 예약 목록 구분(다가오는/지난 예약)**
    - DoD: `/my-reservations`에서 현재 시각 이후 예약은 "다가오는 예약" 섹션에, 이전 예약은 "지난 예약" 섹션에 표시된다.
- **M5: 예약 취소 및 슬롯 복구**
    - DoD: "다가오는 예약"에서 취소 버튼 클릭 시 해당 예약이 목록에서 사라진다.
    - DoD: 취소 직후 해당 시간 슬롯이 트레이너 상세 화면에서 다시 예약 가능 상태로 표시된다.
- **M6: 트레이너 권한 분리**
    - DoD: 트레이너 A 계정으로 로그인 후 `/trainer/schedule`에 트레이너 B의 예약 데이터가 표시되지 않는다.
- **M7: 관리자 전체 현황 조회**
    - DoD: 관리자 계정으로 `/admin/reservations`에 접속하면 오늘 날짜의 전체 예약이 트레이너·회원·시간과 함께 표에 표시된다.

### 🤖 [AI 모델 생성 결과 (기존 프롬프트 기준)]
- **M1: 데이터베이스 설계 및 권한 인증**
    - AC: 회원이 로그인하면 트레이너 목록 화면으로 이동한다.
- **M2: 핵심 예약 시스템 및 회원 흐름**
    - AC: 예약 성공 시 본인의 마이페이지와 트레이너 스케줄에 즉시 표기된다.
    - AC: 동시에 두 명의 회원이 같은 시간의 예약을 시도할 경우, 한 명만 성공하고 다른 한 명에게는 오류 메시지가 노출된다.
- **M3: 트레이너 및 관리자 대시보드**
    - AC: 관리자 계정으로 로그인 시 전체 현황을 볼 수 있다.
- **M4: 모바일 최적화 및 최종 테스트**
    - AC: 모바일 환경에서 깨짐 없이 예약이 가능해야 한다.

## 2. 소규모 공방 원데이클래스 신청 서비스

### 📝 [업무 상세 프롬프트 (요구사항)]
공방을 운영 중인데 원데이클래스 신청을 전부 인스타그램 DM으로만 받다 보니 관리가 엉망입니다. 정원이 찼는지 매번 손으로 세야 하고, 같은 사람이 실수로 두 번 신청해도 걸러지지 않고, 신청자 명단을 확인하려면 DM을 처음부터 다시 스크롤해야 합니다. 클래스 일정을 올리면 손님이 신청하고, 정원이 차면 자동으로 마감되는 웹페이지를 만들고 싶습니다.
사장님(관리자) 계정으로 로그인해서 클래스명, 날짜, 시간, 정원, 가격, 준비물, 간단한 설명을 입력해 클래스를 등록합니다. 등록한 클래스는 손님이 보는 목록 페이지에 카드 형태로 나타나야 하고, 각 카드에는 남은 자리 수가 같이 보이면 좋겠습니다.
손님은 회원가입 없이 클래스를 보고 바로 신청할 수 있으면 좋겠습니다. 신청할 때는 이름, 연락처(전화번호), 인원수를 입력합니다. 정원이 신청 인원까지 포함해서 초과되면 신청 버튼이 막혀야 합니다. 예를 들어 정원 8명 중 7명이 신청된 상태에서 2명으로 신청하려고 하면 막아야 합니다.
관리자는 클래스별로 신청자 명단을 확인할 수 있어야 하고, 이름/연락처/인원수/신청 시각이 표로 정리되어 보이면 좋겠습니다. 나중에 엑셀로 내려받을 수 있으면 더 좋겠지만 이건 MVP 이후로 미뤄도 됩니다.
손님이 신청을 취소하고 싶을 때는 본인이 입력했던 연락처로 본인 신청 내역을 조회해서 취소할 수 있어야 합니다. 취소하면 그만큼 정원에 자리가 다시 생겨야 하고, 마감되어 있던 클래스라면 다시 신청 가능 상태로 바뀌어야 합니다.
같은 손님이 같은 클래스에 실수로 중복 신청하는 것도 막고 싶은데, 이건 같은 연락처로 같은 클래스에 신청 이력이 있으면 안내 문구를 띄우는 정도로 처리해주면 될 것 같습니다.
모바일에서 신청하는 손님이 대부분이라 모바일 화면이 제일 중요합니다. 결제는 현장 결제라 온라인 결제 기능은 필요 없습니다.

### 🎯 [모범 마일스톤 & DoD]
- **M1: 클래스 등록 (관리자)**
    - DoD: 관리자 로그인 후 `/admin/classes/new`에서 클래스명·날짜·정원 입력 후 등록하면 `/classes` 목록에 해당 클래스가 표시된다.
- **M2: 클래스 목록 및 잔여 정원 노출**
    - DoD: `/classes` 접속 시 등록된 클래스 카드에 날짜, 잔여 정원 숫자가 함께 표시된다.
- **M3: 신청 접수 및 인원수 검증**
    - DoD: 클래스 상세에서 이름·연락처·인원수 입력 후 신청 버튼 클릭 시 "신청이 완료되었습니다" 메시지가 표시된다.
    - DoD: 신청 인원수가 잔여 정원을 초과하면 "잔여 인원이 부족합니다" 에러가 표시되고 신청이 처리되지 않는다.
- **M4: 정원 마감 처리**
    - DoD: 정원이 모두 찬 클래스는 신청 버튼이 비활성화되고 "마감되었습니다" 텍스트가 표시된다.
- **M5: 중복 신청 방지**
    - DoD: 동일 연락처로 동일 클래스에 재신청 시 "이미 신청한 클래스입니다" 안내가 표시되고 중복 신청 건이 명단에 추가되지 않는다.
- **M6: 본인 신청 조회 및 취소**
    - DoD: `/my-applications`에서 연락처 입력 후 조회하면 본인이 신청한 클래스 목록이 표시된다.
    - DoD: 취소 버튼 클릭 시 해당 신청이 목록에서 사라지고, 잔여 정원 숫자가 신청 인원수만큼 증가한다.
- **M7: 관리자 신청자 명단 조회**
    - DoD: 관리자가 `/admin/classes/[id]/applicants`에 접속하면 이름·연락처·인원수·신청 시각이 표로 표시된다.

### 🤖 [AI 모델 생성 결과 (기존 프롬프트 기준)]
- **M1: 클래스 등록 및 인증 권한**
    - AC: 관리자 로그인 후 새로운 클래스를 등록할 수 있다.
- **M2: 클래스 신청 및 정원 관리 기능**
    - AC: 손님이 신청을 완료하면 남은 자리가 차감되어 화면에 반영된다.
    - AC: 정원이 초과되면 신청 버튼이 비활성화된다.
- **M3: 중복 신청 방지 및 취소 시스템**
    - AC: 같은 연락처로 재신청 시 안내 문구가 노출되고 신청되지 않는다.
    - AC: 취소 시 정원에 자리가 다시 생기고 다시 신청 가능 상태로 변경된다.
- **M4: 관리자 신청자 명단 조회 및 QA**
    - AC: 관리자 화면에서 전체 신청자 목록을 확인할 수 있다.

## 3. 팀 내부 비품/장비 대여 신청 서비스

### 📝 [업무 상세 프롬프트 (요구사항)]
회사 내부에서 노트북, 카메라, 마이크 같은 장비를 공용으로 빌려 쓰는데 누가 뭘 언제까지 빌렸는지 파악이 안 돼서 장비가 자꾸 사라지거나 필요할 때 없는 일이 반복됩니다. 엑셀 파일로 대여 현황을 관리해봤는데 다들 업데이트를 안 해서 실효성이 없었습니다. 직원이 장비를 대여 신청하고 반납 처리까지 할 수 있는 사내 웹 도구를 만들고 싶습니다.
직원은 사내 계정으로 로그인 후 전체 장비 목록을 봅니다. 장비마다 이름, 카테고리(노트북/카메라/오디오 등), 현재 상태(대여 가능/대여중), 대여중이라면 반납 예정일이 표시되면 좋겠습니다. 대여 가능한 장비를 선택해서 대여 신청을 하면, 반납 예정일을 입력해야 하고 신청 즉시 장비 상태가 "대여중"으로 바뀌어야 합니다.
이미 대여중인 장비는 다른 직원이 신청할 수 없어야 합니다. 대여 신청과 동시에 장비 상태 변경이 반영되어야 다른 직원이 신청서를 작성하는 도중에 장비가 채가는 일이 없어야 합니다.
직원은 마이페이지에서 본인이 현재 대여중인 장비 목록과 과거 대여 이력을 볼 수 있어야 합니다. 반납할 때는 "반납하기" 버튼을 눌러 직접 처리할 수 있어야 하고, 반납 처리되면 장비 상태가 다시 "대여 가능"으로 바뀌어야 합니다.
관리자(총무팀)는 전체 장비의 대여 현황을 한 화면에서 확인할 수 있어야 하고, 누가 언제부터 언제까지 빌렸는지, 반납 예정일이 지났는데 아직 반납 안 된 연체 건이 있는지 확인할 수 있으면 좋겠습니다. 관리자는 필요하면 직원 대신 반납 처리를 할 수 있어야 합니다. 새 장비를 등록하거나 고장/폐기된 장비를 목록에서 제외하는 기능도 있으면 좋겠습니다.
사내용이라 디자인은 최소한으로 해도 되고, 핵심은 지금 어떤 장비가 누구한테 있는지 정확하게 아는 것입니다.

### 🎯 [모범 마일스톤 & DoD]

## 4. 독서 모임 매칭 및 출석 관리 서비스

### 📝 [업무 상세 프롬프트 (요구사항)]
독서모임 커뮤니티를 운영하는데 카카오톡 오픈채팅방으로 매주 모임을 안내하다 보니 몇 가지 문제가 있습니다. 이번 주 모임 정원이 찼는지 실시간으로 파악이 안 되고, 누가 이번 달에 몇 번 참여했는지 기록이 안 남아서 열심히 참여하는 회원을 챙겨주기가 어렵습니다. 모임을 등록하면 회원이 신청하고, 출석까지 체크할 수 있는 웹 서비스를 만들고 싶습니다.
운영자(관리자)는 이번 주 모임의 책 제목, 날짜, 시간, 장소, 정원, 간단한 소개를 입력해서 모임을 등록합니다. 등록된 모임은 회원들이 보는 목록 페이지에 표시되고, 신청 인원과 정원이 함께 보이면 좋겠습니다.
회원은 로그인 후 모임 목록을 보고 참여하고 싶은 모임에 신청 버튼을 누릅니다. 신청 즉시 반영되어야 하고, 정원이 다 찬 모임은 신청 버튼이 비활성화되어야 합니다. 신청했던 회원이 사정이 생겨 못 가게 되면 신청을 취소할 수 있어야 하고, 취소하면 정원에 자리가 다시 생겨서 다른 회원이 신청할 수 있어야 합니다.
모임 당일에는 운영자가 출석 체크 화면에서 그 모임에 신청한 회원 목록을 보고 한 명씩 참석/불참으로 표시합니다. 출석 체크는 그 자리에서 바로 처리되어야 다음 모임 안내할 때 활용할 수 있습니다.
회원은 자기 마이페이지에서 지금까지 신청했던 모임 이력과 실제 출석한 횟수를 확인할 수 있으면 좋겠습니다. 나중에 "이번 달 개근 회원" 같은 걸 뽑아서 소소한 혜택을 주고 싶은데, 이건 지금 당장은 아니어도 됩니다. 운영자는 전체 회원 중 참여율이 저조한 회원을 파악할 수 있도록, 관리자 화면에서 회원별 누적 신청/출석 횟수를 볼 수 있으면 좋겠습니다.

    - DoD: 운영자가 `/admin/meetings/new`에서 모임 정보 입력 후 등록하면 `/meetings` 목록에 표시된다.

    - DoD: 회원이 `/my-page`에 접속하면 본인이 신청한 모임 목록과 각 모임의 출석 여부가 표시된다.
    - DoD: 관리자가 `/admin/members`에서 특정 회원의 누적 신청 횟수와 누적 출석 횟수를 확인할 수 있다.

## 5. 반려동물 병원 예진표 사전 작성 서비스

### 📝 [업무 상세 프롬프트 (요구사항)]
동물병원을 운영하는데 내원 전에 보호자가 증상을 미리 작성해오면 진료가 훨씬 빨라질 것 같습니다. 지금은 접수할 때 보호자에게 종이 문진표를 주고 작성하게 하는데, 대기실에서 작성하다 보니 시간이 걸리고 글씨를 못 알아볼 때도 많습니다. 보호자가 방문 전에 미리 반려동물 정보와 증상을 입력해두고, 병원에서는 접수 순서대로 예진표를 확인할 수 있는 서비스를 만들고 싶습니다.
보호자는 회원가입 없이 전화번호만 입력하면 바로 예진표를 작성할 수 있으면 좋겠습니다. 예진표에는 반려동물 이름, 종(강아지/고양이 등), 나이, 몸무게, 증상, 증상이 시작된 시점, 방문 희망 시간, 특이사항(알레르기, 기존 병력 등)을 입력합니다. 필수 항목(이름, 증상)이 비어있으면 제출이 안 되어야 합니다.
같은 보호자가 같은 날 실수로 예진표를 두 번 제출하는 경우를 막고 싶습니다. 같은 전화번호로 같은 날 이미 제출한 예진표가 있으면, 새로 제출하는 대신 기존 예진표를 수정할 수 있게 안내해주면 좋겠습니다.
병원 직원(관리자)은 관리자 화면에서 오늘 접수된 예진표를 제출 시간 순서대로 확인합니다. 각 예진표를 클릭하면 상세 내용을 볼 수 있어야 하고, 진료가 시작되면 "진료중"으로, 끝나면 "완료"로 상태를 바꿀 수 있어야 합니다. 대기 중/진료중/완료 상태를 색이나 배지로 구분해서 한눈에 보이면 좋겠습니다.
보호자가 제출 후 본인 예진표 상태(대기중인지, 진료가 시작됐는지)를 확인할 수 있으면 대기실에서 마냥 기다리지 않아도 되니 좋을 것 같은데, 이건 시간이 되면 넣어주세요. 예약 시스템까지는 이번 MVP에 포함하지 않고, 어디까지나 "미리 증상을 적어두는" 사전 문진표 기능에 집중해주세요.

### 🎯 [모범 마일스톤 & DoD]
- **M1: 예진표 작성 폼**
    - DoD: `/pre-check`에서 반려동물 이름·증상 등 입력 필드와 제출 버튼이 표시된다.
- **M2: 필수값 검증**
    - DoD: 증상 필드를 비운 채 제출 클릭 시 완료 메시지가 표시되지 않고 폼이 그대로 유지된다.
    - DoD: 이름 필드를 비운 채 제출 클릭 시에도 동일하게 제출이 처리되지 않는다.
- **M3: 제출 처리**
    - DoD: 필수 항목을 모두 입력 후 제출 클릭 시 "예진표가 접수되었습니다" 메시지가 표시된다.
- **M4: 당일 중복 제출 방지 및 수정 안내**
    - DoD: 같은 전화번호로 같은 날 두 번째 제출 시도 시 "오늘 이미 접수된 예진표가 있습니다" 안내와 함께 기존 예진표 수정 화면으로 연결된다.

    - DoD: 관리자가 `/admin/pre-checks`에 접속하면 오늘 제출된 예진표가 제출 시각 오름차순으로 표시된다.

    - DoD: 목록에서 특정 예진표를 클릭하면 반려동물 정보와 증상 등 전체 내용이 상세 화면에 표시된다.
- **M7: 진료 상태 변경**
    - DoD: 관리자가 "진료 시작" 클릭 시 해당 예진표 상태가 "진료중"으로 바뀐다.
