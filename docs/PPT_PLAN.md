## 발표 조건

- **자리**: 부트캠프 최종 발표
- **시간**: 20분 (발화 17분 + 시연영상 3분)

## 핵심 결정 사항

- **1순위 타깃**: 대표님. 개발자용 디테일은 Q&A에서 받음
- **딥다이브 2개**: ①SOW 생성(문장 품질) ②GitHub 검수(룰기반→atom 조합). 각각 시행착오 서사로 구성
- **1세대 100% 지표**: 일부러 보여주고 "틀렸다"는 반전 장치로 사용 (S15)
- **False FAIL 40.6%**: 올림. "나쁜 코드를 통과시키진 않는다 / 아직 좋은 코드를 실패로 볼 때가 있다"로 프레이밍
- **BM**: 간단히. 회사=구독제(채용·관리까지 무료, 검수부터 구독), 프리랜서=수수료
- **프리셋**: 정직하게 "1종 실증 + 확장 구조 확보"
- **테스트넷 코인**: "별미"가 아니라 해외 외주라는 전제가 강제한 구조의 일부

## 섹션 1. 문제 정의 & 시장 조사 (4분, 6장)

### S1 — 타이틀

- **정보구조**: 타이틀 1장

### S2 — 창업의 허들이 무너졌다

- **목적**: "왜 지금인가"를 3초에
- **헤드라인**: AI가 개발 허들을 낮췄다 → 창업가도, 프리랜서도 늘었다
- **정보구조**: 두 곡선이 같이 오르는 그림 1개 (좌우 2단 지표 카드 또는 이중선 그래프)

**조사 완료 — 쓸 수 있는 숫자:**

| 지표 | 수치 | 출처 |
|---|---|---|
| 신설법인 추이 | 2017 **9.8만** → 2018 **10.2만** → 2019 **10.9만**(사상 최고) → 2020 **12.3만** → 2023 **~13만** | 중소벤처기업부 창업기업동향 |
| 긱워커 규모 | 2020 **704만 명** → 2024 **869만 명** (+165만, 4년) | 머니터링 |
| 긱워커 중개 시장 | 2020 **9,267억 원** → 2025(전망) **1조 1,903억 원** | 이지경제 |
| 크몽 성장 | 연 40~50% 성장, 2025.2 누적 회원 **400만** 돌파 | 크몽 공식 |

> **⚠ 조사 미완**: 신설법인 2021~2022 구간 숫자가 검색으로 확정 안 됨. 2022년에 역대 최고 후 2023에 6% 감소했다는 보도도 있음. 꺾은선을 그리려면 중소벤처기업부 「2024년 연간 창업기업동향」 PDF를 직접 열어 2020~2024 5개년 수치를 확인해야 함. 또는 시점 2개만 대비(2020 vs 2024)로 가면 검증된 숫자만 사용 가능.

### S3 — 그들이 먼저 하려는 것은 MVP

- **헤드라인**: 큰 투자 전에, 작게 만들어 확신을 얻고 싶다
- **담을 것**: MVP를 만드는 이유(아이디어 검증), 사내 개발자 없음 → 외주로 향함
- **정보구조**: 3단 스텝 (아이디어 → MVP → 확신)

**조사 결과**: "초기 스타트업 중 몇 %가 외주를 쓴다"는 공개 설문 데이터 없음. 대신:
- 위시켓 누적 프로젝트 수 **73,213개** (2025~2026.3 기준) — 규모 증거로 사용 가능
- 이 슬라이드는 통계 없이 논리 전개 + "위시켓 7만 건"으로 충분히 성립

### S4 — 국내 외주는 비싸다

- **목적**: 해외로 눈을 돌리는 이유의 수치적 근거
- **헤드라인**: MVP 하나에 수천만 원. 검증 전 지출로는 너무 크다
- **정보구조**: 좌우 비교 (국내 / 해외) + 배수 강조

**조사 완료 — 쓸 수 있는 숫자:**

| 구분 | 비용 | 출처 |
|---|---|---|
| **국내 웹 MVP** | **1,500만 ~ 3,000만 원** | 위시켓 실데이터 (73,213개 프로젝트) |
| **국내 앱 평균** | **3,270만 원** (최소 250만 ~ 최대 2억) | 위시켓 |
| **동남아 개발자 시급** | **$15~35/hr** | index.dev, aalpha.net |
| **동유럽 개발자 시급** | **$40~70/hr** | 같은 출처 |
| **북미 개발자 시급** | **$80~140/hr** | 같은 출처 |

**배수 (핵심 숫자)**:
- Gridge 블로그 직접 인용: "동일한 기능 범위를 베트남 개발팀에 위탁하면 **국내 대비 40~60% 수준의 비용**"
- 즉 같은 MVP 기준: 국내 ~2,000만 원 vs 동남아 ~800만~1,200만 원
- **"절반 이하. 그런데 세 가지 벽이 있다"** → S5로 넘기기

### S5 — 해외로 눈을 돌리면, 벽이 세 개

- **목적**: 이 장이 곧 제품 구조. S8과 1:1로 맞물림. 가장 중요한 장
- **헤드라인**: 싼 건 알겠는데, 어떻게 뽑고·합의하고·확인하나
- **정보구조**: 3열 카드

**담을 것 (순서 고정 — S8과 대응):**
1. **찾을 곳이 없다** — 마땅한 플랫폼 부재, 포트폴리오만으로 역량 판단 불가
2. **말이 안 통한다** — 요구사항은 한국어, 계약 문서는 영어여야 함
3. **결과물을 확인할 수 없다** — 코드가 GitHub에 올라와도 비개발자는 작동 여부를 모름. 대면 확인도 불가

**조사로 확보한 근거:**
- 프리모아 기사: "해외 개발자 수준은 높아졌지만 관건은 소통의 장벽 해결" — 브릿지 매니저를 따로 둬야 함
- Medium 기고: "아무리 열심히 커뮤니케이션을 해도 기대와 목표의 차이가 좁혀지기 어렵다"
- Gridge: "도급형 외주는 납품에 강하지만, 유지보수 시 인력 단절 — 검증 기회가 납품 시점 한 번뿐"

### S8 — 벽 3개 ↔ 기능 3개

- **목적**: 기능이 취향이 아니라 문제에서 나왔음을 증명

| 벽 | 기능 |
|---|---|
| 찾을 곳이 없다 | 수행 제안서 원문 기반 선정 (AI 점수 없음 — 사람이 읽고 고른다) |

| 확인할 수 없다 | **Commit SHA 고정 + 격리 환경 실행 검수** |

- **정보구조**: 2열 대응표
- **말할 것**: "영어 SOW와 USDC는 기능을 늘린 게 아니라, 해외 외주라는 전제가 강제한 겁니다"

### S9 — 전체 제품 흐름도

- **헤드라인**: 앞 단계의 결과가 다음 단계의 입력이 된다
- **정보구조**: 가로 파이프라인. 승인 버전과 SHA가 **고정(잠금)되는 지점 2곳**을 시각적 표시

```
프로젝트 등록 → 수행 제안서 제출 → 발주자가 원문 검토·선정
  → AI가 SOW·마일스톤·DoD 초안 → 🔒 양측 승인으로 버전 고정
  → PR 제출 시 🔒 head Commit SHA 고정 → 격리 환경에서 설치·빌드·실행
  → DoD별 통과/실패/확인필요 + 증거 → 발주자 최종 승인
  → 인보이스·지급 → 통합 증빙
```

- **근거 파일**: `README.md` User Flow, `docs/MILESTONE_VERIFICATION_DESIGN.md`

### 딥다이브 ① SOW 생성 (3분, 5장)

### S12 — 시작은 룰기반이었다

- **헤드라인**: 문장 개수를 세서 마일스톤을 나눴다
- **정보구조**: 코드 인용 + 번역 실패 3개를 큰 글씨로

**담을 것** (전부 커밋 `c6f9377`, 08-11, `src/lib/rag-translator.ts`에서 확인됨):
- 마일스톤 개수 = **입력 문장 개수로 결정** (1문장→1개, 3문장 이하→2개, 나머지→무조건 3개)
- 금액은 **0.2 / 0.5 / 0.3 고정 분배**
- M1은 항상 "설계 및 시스템 기초 셋업", M3은 항상 "QA 테스트 및 배포" — **하드코딩**
- M2만 키워드 매칭: `"결제"||"장바구니"` → 이커머스, `"대시보드"` → 어드민
- 기간에 `"08.15 - 09.05"`가 **문자열로 박혀 있었음**
- 한→영 사전 매칭 결과: **"반차" → "Half car"**, **"가계약" → "Fake contract"**, **"전자결재 워크플로우" → "전자Payment 워크플로우"**

**말할 것**: 번역 3개는 웃고 넘어가되, "입력을 이해하지 않고 형태만 맞춘 결과"로 마무리.

### S15 — 반전: 우리가 낸 100% 리포트는 틀렸다 ⭐ 절대 빼지 말 것

- **목적**: 발표 전체에서 가장 신뢰를 얻는 장
- **헤드라인**: 모든 지표가 100%였다. 저울이 고장나 있었다

**담을 것:**
- 1세대 리포트: URL 명시율 0%→100%, 엣지케이스 분리 0%→100% — "Playwright 100% 자동화 가능"
- 계측 코드를 열어보니:
  - URL 판정 정규식이 **`CSV/Excel`, `ERP/CRM`, `A/B`를 URL로 세고 있었음**
  - 리포트 달성 표시 `✅`가 **문자열 하드코딩** → 89.9%가 "90% 이상" 목표에 ✅, 11.74초가 "8초 미만" 목표에 ✅
  - 생성된 DoD 원문을 저장하지 않아 **재채점 자체가 불가능**
